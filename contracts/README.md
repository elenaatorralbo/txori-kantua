# Contracts

Source of truth of the interfaces between modules. If this directory and a
document in `docs/` disagree, this directory wins: it is what the tests run.

| File | What it defines |
|---|---|
| `mqtt/common.schema.json` | Shared types: version, `event_id`, `station_id`, timestamp, service |
| `mqtt/detection.schema.json` | Bird detection event |
| `mqtt/environment.schema.json` | Environmental readings event |
| `mqtt/health.schema.json` | Station health event |
| `mqtt/availability.schema.json` | `online`/`offline` state of a service and its Last Will |
| `openapi.yaml` | Read-only REST API `/api/v1` |
| `examples/valid/` | Messages that **must** be accepted |
| `examples/invalid/` | Messages that **must** be rejected, each one with its reason |

Status: **proposed**, pending team review
([#10](https://github.com/elenaatorralbo/txori-kantua/issues/10)). Every
example is synthetic; none comes from a working station.

## How to check them

```bash
python -m venv .venv && source .venv/bin/activate   # on Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest tests/contracts
```

No hardware or broker is needed.

## How to use them from code

Whoever **produces** data does not write JSON by hand:

```python
from txori_kantua import messaging as m

event = m.new_detection(
    station_id="station-01",
    scientific_name="Turdus merula",
    confidence=0.87,
    observed_at=window_start,      # timezone-aware datetime, or RFC 3339 string with Z
    window_end=window_end,
    model_name="BirdNET",
    model_version=model_version,
)
payload = m.encode("detection", event)              # validates and serialises
topic = m.topic_for("detection", "station-01")      # txori/v1/station-01/detections
policy = m.POLICIES["detection"]                    # qos=1, retain=False
```

Equivalents: `m.new_environment(...)` with `m.reading(value, unit, quality)`,
`m.new_health(...)` and `m.availability(...)`.

Whoever **consumes** always validates at the boundary and never stops because
of a bad message:

```python
try:
    kind, event = m.decode(topic, payload)
except m.UnsupportedSchemaVersion:
    ...   # producer newer than me: log and carry on
except m.MessagingError:
    ...   # invalid, oversized message or foreign topic: log and carry on
```

From another language or tool it is enough to validate against the
`.schema.json` files (JSON Schema 2020-12) and apply the extra rules below.

## Rules JSON Schema cannot express

They are applied by `txori_kantua.messaging.validate` and covered by the tests.
An external validator has to implement them separately.

| Rule | Reason |
|---|---|
| `window_end` later than `observed_at` in detections | An empty or inverted window is not an observation |
| Dates must exist in the calendar | The pattern accepts `2026-02-30`; the calendar does not |
| Message `station_id` equal to the topic one | Broker ACLs apply to the topic; without this rule a producer could attribute data to another station |
| Message `service` equal to the topic one, for availability | Same as the previous one |
| Serialised message ≤ 16 KiB, checked before deserialising | A real event takes hundreds of bytes; close to the limit it is suspected of carrying something that is not metadata |
| Major version other than 1 → `UnsupportedSchemaVersion`, not "invalid message" | The consumer must be able to tell an out-of-step deployment from a broken producer |

## Identity, timestamps and retries

- **`event_id`** is generated by the producer once per logical observation and
  kept on every retry. Retrying is resending the same bytes, not building the
  event again. `m.stable_event_id(...)` gives a deterministic identifier for a
  producer that can recompute the same observation after restarting.
- **`observed_at`** is when it happened (start of the audio window, or instant
  of the reading). The producer sets it and a retry does not change it.
- **`received_at`** is when ingest received it **for the first time**. The
  consumer adds it: it is not part of any MQTT message and a message carrying
  it is rejected. It only appears in API responses.
- Every timestamp is RFC 3339 in **UTC with a `Z` suffix**, without offsets.
  Up to nanoseconds are accepted; storage truncates to milliseconds
  ([ADR 0003](../docs/adr/0003-persistence.md)).
- **QoS 1** everywhere: at-least-once delivery, with possible duplicates.
  Deduplication by `event_id` is the consumer's obligation
  ([ADR 0002](../docs/adr/0002-event-transport.md)).
- **Events** (detection, environment) are not retained. **State** (health,
  availability) is, and whoever reads it always checks its `observed_at`.
- `availability` carries no `event_id`: the Last Will is built before the
  failure. Its identity is `(station_id, service, status, observed_at)`.

## Privacy in the contract

Every schema has `additionalProperties: false`. It is not a style detail: it is
what makes a message with `audio_b64`, a file path, a transcription or
coordinates be **rejected by the contract**. There are negative examples of
each case in `examples/invalid/`.

## How to change a contract

- **Compatible** (new optional field, new value that consumers ignore without
  breaking): increase the minor version, `1.0` → `1.1`, and add examples.
  Consumers accept any `1.x`.
- **Incompatible** (removing or renaming a field, changing a unit or a
  meaning): topic `txori/v2/...` or prefix `/api/v2`, with a migration plan
  agreed with every consumer. A published contract is not edited in place.
- In both cases, schema, valid and invalid examples and tests go in the **same
  PR**. A contract without a negative example is not finished.
